---
description: Переписать редакционный черновик по пометкам владельца и проверить заново
argument-hint: <дата YYYY-MM-DD> <draft_id> <путь к файлу с пометками>
---
Аргументы: $ARGUMENTS (дата, draft_id, путь к файлу пометок).
Режим безголовый: субагентов вызывай только синхронно (`run_in_background: false`), не завершай ход до шага 6.

1. Прочитай `runs/<дата>/drafts/<draft_id>.json` и файл пометок.
2. Определи новую версию: `<draft_id без суффикса -vN>-v2`, если такой файл есть — `-v3` и т. д.
Пометки владельца — главное требование, важнее сохранения исходного текста. Конкретные правила:
- «короче» / «сократи» — новый текст минимум на 25% короче исходного по числу символов (посчитай оба);
- «убери X» — X не упоминается вообще;
- «упор на Y» — Y в первом абзаце и в выводе.
3. Вызови субагента tg-editor (канал `tg_editorial`) или vk-editor (`vk_editorial`) — по полю `channel` черновика — с задачей: переписать черновик строго по пометкам (передай их дословно и правила выше), факты и источники брать только из исследования; записать `runs/<дата>/drafts/<новый id>.json` (id внутри = новый id). Исследование — `runs/<дата>/research/<slug>.json`, slug = id без суффиксов `-r`/`-vN`.
4. Вызови субагента critic для нового черновика, передав ему дословно пометки владельца и длину исходного текста: вердикт ok только если правила пройдены И пометки выполнены (для «короче» — проверь числа). Вердикт в `runs/<дата>/verdicts/<новый id>.json`.
5. Если critic отклонил из-за невыполненных пометок — один раз верни редактору с причиной (та же версия), затем снова critic.
6. Последним сообщением выведи: путь к новому черновику, длину было/стало и вердикт (ok, причина одной строкой).
Ничего не публикуй.
