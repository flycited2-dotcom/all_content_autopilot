# Резерв диалога Claude → ChatGPT

Обновлено 22 октября 2026 года.

## Что реализовано

Слушатель сначала обращается к Claude. Если подтверждён лимит, ошибка входа,
временная недоступность или неверный формат ответа, диалог продолжает ChatGPT.
Модель возвращает JSON-намерение; действия выполняет прежний серверный код.
Codex CLI, его авторизация и платные API-ключи здесь не используются.

ChatGPT подключается через **Sign in with ChatGPT** с разрешением использовать
доступный план аккаунта. Этот способ предусмотрен для открытых и локальных приложений;
фактические разрешения, модели и лимиты определяет сервис для выбранного аккаунта.
Наличие подписки или успешный вход ещё не доказывают доступность конкретной модели.

Подключение не читает существующие беседы ChatGPT. Контекст передаёт сам оркестратор:
сообщение, данные каталога и журнала действий, последние 6 пар реплик и, при явном
ответе на черновик, его текст. Товары и цены не придумываются.

## Подключение на ПК

В PowerShell из папки проекта:

```powershell
python -m pip install -r requirements-pc.txt
python -m listener.chatgpt_auth login
```

Откроется официальный браузерный вход. Выберите аккаунт и разрешите подключение
**Agents MY Orchestrator**. Callback принимает только `127.0.0.1` с `/auth/callback`;
публичный порт открывать не нужно. После завершения программа выводит безопасный статус
с `"ready": true`. По умолчанию окно входа ожидается 180 секунд.

Пароли и токены не вводятся в исходники, настройки проекта или чат. На Windows
учётные данные шифруются DPAPI для текущего пользователя в
`runs/private/chatgpt-credentials.dat`; на Unix применяются права 0600. Весь `runs/`
исключён из Git. Расшифровка возможна только приложением от имени того же пользователя
Windows. Перенос зашифрованного файла другому пользователю не является настройкой входа.

Авторизация проверяет подпись ID token, issuer, audience, nonce и выбранный аккаунт.
Обновление входа сериализовано между процессами; временный сетевой сбой не удаляет
регистрацию. Подтверждённый отзыв/истечение refresh token требует повторного входа.

## Включение в работающем слушателе

После успешного входа обновлённый слушатель нужно один раз перезапустить. Сначала
убедитесь, что он не выполняет текущую генерацию. Не запускайте второй экземпляр рядом
с задачей Планировщика.

```powershell
Stop-ScheduledTask -TaskName 'AgentsMY Listener'
# Дождаться завершения старого слушателя; он проверяет остановку своего родителя.
Start-ScheduledTask -TaskName 'AgentsMY Listener'
```

После входа уже работающий **обновлённый** слушатель обнаружит подключение автоматически,
даже если ранее записал `login_required`. Перезапуск нужен для загрузки новой версии кода,
а не при каждом обновлении OAuth.

Далее отправьте обычное сообщение боту. При подтверждённом лимите Claude появится одно
уведомление о переходе на ChatGPT. После времени восстановления следующий запрос снова
проверит Claude и при успехе вернёт основной режим.

## Модели и лимиты

По умолчанию выбирается первая модель с `visibility=list` из каталога выбранного аккаунта
в порядке сервиса. Чтобы закрепить доступный slug, можно задать пользовательскую переменную
`ORCH_CHATGPT_MODEL` и перезапустить слушатель. Произвольное название, отсутствующее в
каталоге аккаунта, отклоняется; скрытого перехода на API-биллинг нет.

Состояние обработчиков сохраняется в `runs/chat/providers.json` и переживает перезапуск:

- Claude usage limit: до явно указанного времени сброса; если его нет — проверка через час.
- ChatGPT usage limit: проверка через час, если сервис не указал допустимое время повтора.
- Короткое ограничение частоты: `Retry-After`, иначе пауза 60 секунд.
- Ошибка сети: пауза 30 секунд; таймаут — 60 секунд.
- Ошибка входа или настройки: пауза 5 минут и безопасная диагностика в журнале.

Это реакция на ошибки реальных запросов, а не обещание заранее знать остаток лимита.
HTTP 429 сам по себе не трактуется как исчерпание подписки: учитывается код ошибки.
Ответ ChatGPT успешен только после `response.completed`; незавершённый поток и частичный
текст не отправляются серверу как намерение.

## Очереди и повторные попытки

Текущее сообщение сначала сохраняется в `runs/chat/pending-turn.json`. Если недоступны
оба обработчика, сервер не получает успешное пустое намерение: сообщение ждёт в этой
локальной очереди. Новые сообщения остаются в серверной очереди. Бот уведомляет владельца
об ожидании без повтора этого уведомления на каждом опросе.

После генерации намерение сохраняется до отправки серверу. Потеря HTTP-ответа повторяет
тот же `message_id` и то же намерение, а не вызывает модель повторно. Серверная защита от
дубликатов остаётся необходимой: эта реализация не гарантирует «ровно один раз» при
аварии самого VPS посреди внешнего действия. Известные серверные риски описаны в обзоре.

Редакционные задачи передаются в долговечную очередь
`runs/chat/editorial-queue.json` со стабильным ключом `message_id:index`. Подтверждённый
лимит Claude сохраняет их до восстановления. Готовые принятые черновики доставляются
на сервер с сохранением прогресса, без повторной генерации при сетевом сбое.

**На этом этапе ChatGPT резервирует диалог и разбор команд.** Полный редакционный прогон
(исследователь, редакторы, критик, утренние материалы и правки текста) остаётся на Claude.
При его лимите эти задания ожидают; товарные команды и вопросы боту могут обрабатываться
через ChatGPT. Генерация изображений и публикации сохраняют прежний путь.

## Диагностика

```powershell
python -m listener.chatgpt_auth status
python -m listener.routing status
Get-Content runs/chat/listener.log -Tail 80
```

`chatgpt_auth status` показывает только локальную готовность входа. Он не расходует лимит,
не делает сетевых запросов и не гарантирует доступность модели прямо сейчас.
`routing status` показывает активный обработчик, категории ошибок, времена повторов и
наличие ожидающего сообщения. Никаких токенов эти команды не выводят.

Если доступ восстановлен раньше, можно запросить повторную проверку без перезапуска:

```powershell
python -m listener.routing retry
```

Команда оставляет сигнал работающему слушателю. Это не самостоятельный запрос модели;
проверка произойдёт при следующем ожидающем сообщении или редакционном задании.

Повреждённые локальные очереди не удаляются автоматически. Не удаляйте их ради
«разблокировки» — сначала сохраните копию и выясните, была ли задача выполнена сервером.
Старые обращения, которые прежняя версия уже закрыла пустым ответом, автоматически
не переигрываются: товарную команду безопаснее повторить после проверки текущего статуса.

## Проверка изменений

Тесты не используют реальные аккаунты, модели, VPS или каналы. Проверяются OAuth
PKCE/nonce/подпись, отказ при смене аккаунта, обновление токенов, завершение потока,
переключение и возврат, строгие поля намерения, сохранение очереди и повтор после потери ACK.
На Windows проверка Unix-прав пропускается.

```powershell
python -m pytest -q --basetemp=runs_test/failover-check --tb=short
```

Каталог `--basetemp` должен быть специально выделен для тестов: pytest очищает его.
Для тестового HTTP на localhost окружение должно разрешать локальные соединения.
