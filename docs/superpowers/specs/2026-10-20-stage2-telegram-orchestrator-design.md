# Этап 2: Telegram-оркестратор и голос — дизайн

_Дополняет спек `2026-10-13-content-factory-orchestrator-design.md` (этап 2). Обсуждено с владельцем 2026-10-20._

## Зачем

Владелец один, основная работа — тендеры. Самое затратное в контенте сейчас — **утренняя постановка товарных задач**: ночью скрипты обновили сайт, прайсы и почту, утром владелец вручную, кнопка за кнопкой в мастере `/task` бота @Sendpr1ce_bot, выбирает, что и когда выкладывать («до обеда — одна группа, после обеда — другая», «из пришедшего прайса — вот эти позиции»). Цель этапа — чтобы это делалось одной голосовой фразой в отдельном закреплённом чате, а кнопки оставались запасным путём.

Слова владельца: «Я встал, подумал, надиктовал». «Если он понимает, зачем мне каждый раз контролировать». «Днём ничего не ждал… вечером, наверное, сводка: что проделано, что не проделано».

## Цели

1. **Отдельный бот оркестратора** (создаёт владелец в @BotFather), закреплённый чат; отвечает только владельцу.
2. **Голос — основной ввод, текст и кнопки — запасной.** Любое действие можно сделать без голоса.
3. **Товарные задачи из речи.** Фраза вида «до обеда — X, после обеда — Y, из нового прайса — Z, бренда такого-то не больше трёх» превращается в задачи content-factory тем же механизмом, что `/make` и `/task` (`ExcelStore.select_items`, расписание ЧЧ:ММ, квоты по брендам).
4. **Редакционные посты TG/ВК** запускаются из чата («сделай на завтра пару экспертных постов про …») → существующий `/morning-run` → итог и черновики приходят в чат как предпросмотр.
5. **Вечерняя сводка** в 21:00: что поставлено, что сделано, что упало, сколько заявок, был ли ПК на связи.
6. **Работа при выключенном ПК:** бот принимает сообщения, отвечает «принял, разберу, когда ПК будет на связи», отдаёт статус и сводку без нейросети; запасные кнопки работают.

## Не цели (этого этапа)

- Менять путь публикации: товарные посты по-прежнему проходят канал проверки @Sendpr1ce_bot с ✅/❌/🔄/💰; редакционные — только предпросмотр, без публикации.
- Публикация сразу в клиентскую группу владельца вместо канала splithub.ru — позже, отдельным решением.
- Авито, видео, переключение ВК-юнитов на основной код, перенос «мозга» на VPS.

## Анти-цели (провал, даже если «работает»)

- **Зафиксированные списки категорий или тем.** Категории в речи владельца — примеры. Бот сопоставляет слова с тем, что **сегодня реально есть** в источниках (прайсы, сайт, почта), и не держит своих списков. Темы ВК каждый раз предлагают агенты.
- Бот выдумывает товары, цены, количества или бренды, которых нет в каталоге.
- Действие по ослышке: распознанная фраза всегда видна владельцу («🎙 Услышал: …»), а всё, что бот поставил, отменяется одной кнопкой.
- Дублирование логики `/task` и `/make` вместо её переиспользования.
- Сообщения днём без повода.

## Решения о поведении

- **Автономия (решение исполнителя, владелец делегировал):** задачу, в которой бот уверен, он **ставит сразу** и отвечает «Поставил: … [Отменить]». Это обратимо до публикации, а публикация защищена кнопками канала проверки. **Переспрашивает только при сомнении:** совпадений в каталоге нет; совпадений подозрительно много (порог — настройка, по умолчанию > 40 позиций на одну группу); группа или бренд распознаны неоднозначно. Вопрос — с кнопками вариантов.
- **Днём бот молчит:** пишет только в ответ владельцу или при сбое, который требует его (например, ПК не на связи больше 12 часов при ожидающих сообщениях).
- **Голос:** под каждым голосовым бот сразу показывает расшифровку; модели и артикулы на слух ненадёжны — для них бот предлагает выбрать из списка кнопками.
- **Контекст дня:** разговор за день — одна сессия Claude (продолжается между сообщениями); новая сессия каждый день в 04:00.

## Как устроено (решения исполнителя — владелец отдал технические решения)

```
Владелец ⇄ бот оркестратора (Telegram)
   │
VPS: orchestrator-bot (systemd, Python 3.12, /opt/agents-my)
   ├─ long-poll Bot API, только chat_id владельца
   ├─ входящие → SQLite-очередь; голос → расшифровка → «🎙 Услышал: …»
   ├─ без ПК: /status, /report, кнопки «Отменить», запасное меню
   ├─ локальный HTTP API 127.0.0.1 (токен), как у фото-агента :8765
   └─ исполнитель действий → `python -m content_factory.agent_cli …` (venv content-factory)
            ▲  SSH-туннель (схема remote_agent.py фото-агента)
ПК: agent-listener (Python, автозапуск Планировщиком Windows при входе)
   ├─ забирает новые сообщения + контекст (сводка каталога, очередь дня)
   ├─ claude -p … --resume <сессия дня> в Agents_MY, песочница headless
   │     → ответ в виде JSON-намерения (схема ниже), без инструментов записи
   └─ отправляет намерение на VPS; VPS проверяет и исполняет; ответ — в чат
```

**Почему так:**
- **Нейросеть не пишет в базу и не публикует.** Она возвращает намерение; VPS проверяет его по белому списку и исполняет кодом content-factory. Песочница этапа 1 сохраняется.
- **Логика задач — в content-factory**, новым модулем `content_factory/agent_cli.py` с тестами, который вызывает тот же код, что `/make` и `/task`. Позже (этап 3) этот же модуль обернётся factory-MCP.
- **Голос — на VPS**, чтобы расшифровка и эхо работали при выключенном ПК. Модель — `faster-whisper` small (int8, CPU): ≈ 0,5 ГБ памяти, ≈ 250 МБ диска. **Первый шаг плана — проверка на 5 реальных голосовых владельца** (длинная диктовка, шум, бренды); если качество или скорость не устроят — `medium` на ПК, а на VPS только запись и «принял».

**Намерение (JSON от Claude):**
```json
{"reply": "текст владельцу",
 "actions": [
   {"type": "enqueue_products", "category": "слова владельца", "count": 10,
    "quotas": {"beko": 3}, "source": "slot|null", "at": "ЧЧ:ММ|null", "day": "сегодня|завтра|YYYY-MM-DD"},
   {"type": "cancel", "task_ref": "…"},
   {"type": "revise_editorial", "draft_id": "…", "notes": "…"},
   {"type": "run_editorial", "brief": "…", "channels": ["tg_editorial", "vk_editorial"]},
   {"type": "ask", "question": "…", "options": ["…"]}
 ]}
```
VPS для `enqueue_products` сопоставляет `category` с сегодняшним каталогом через `agent_cli resolve`; если сработало правило сомнения — превращает действие в `ask` с кнопками.

**Сценарий без ПК:** heartbeat слушателя старше 2 минут → «Принял, разберу, когда ПК будет на связи»; сообщения ждут в очереди и обрабатываются по порядку после включения. Расшифровка голоса работает и без ПК.

**Вечерняя сводка:** таймер VPS 21:00, без нейросети: задачи дня (поставлено/сделано/упало), опубликовано, заявки «📩 Заказать», редакционные черновики, статус ПК.

## Уточнения после проверки дизайна

- **Как `agent_cli` попадает на прод (решение исполнителя).** Первая задача плана — выкатить канон `content-factory` (`feat/aru-post-details`) на прод: по сверке 2026-10-19 его `src/` совпадает с сервером, кроме порядка кнопок в `control_menu.py`. Перед выкладкой — бэкап `/opt/content-factory/src` и `deploy/`, после — прогон дымовых команд из `DEPLOY.md` §4; откат — распаковка бэкапа. Выкладка — только с подтверждения владельца в момент выполнения. Правило 4 `CLAUDE.md` («не трогаешь content-factory») относится к оркестратору во время работы, а не к разработке этапа.
- **Время в «до обеда — X».** Значит то же, что в `/task`: к этому времени превью готовы в канале проверки, публикация — после ✅ владельца, как сейчас (поэтапная автономия). Один срок на всю группу, как в `/task`. Отложенная публикация после одобрения — не в этом этапе.
- **Голосовые правки редакционных черновиков входят в этап** (владелец выбрал «правки к черновикам»): действие `{"type": "revise_editorial", "draft_id": "…", "notes": "…"}` → на ПК редактор переписывает черновик с этими пометками, critic проверяет заново, новый предпросмотр приходит в чат.
- **Расшифровка — кандидаты для проверки:** `faster-whisper` small на VPS, `medium` на ПК и уже работающий в cf-bot бесплатный Google Speech (`bot/voice.py`, без модели и диска). Критерий: бренды и группы из 5 голосовых владельца распознаны верно; эхо короткой команды < 10 с, диктовки до 2 минут < 60 с; ни один фрагмент не теряется молча. Выбор — по результату, фиксируется в плане. **Образцы:** владелец записывает 5 голосовых, как утренний бриф, в «Избранное» Telegram; исполнитель забирает их через личный Telegram-MCP только на чтение и удаляет локальные копии после проверки.
- **Пользователь и права на VPS (решение исполнителя).** `orchestrator-bot` работает от root, как остальные сервисы content-factory (ему нужна запись в их `state`). Слушатель с ПК ходит **отдельным ключом, ограниченным пробросом одного порта** (`permitopen`, без shell), как ключ фото-агента; добавление ключа в `authorized_keys` — с подтверждения владельца.

## Ограничения

- **Диск VPS занят на 90% (свободно 7,2 ГБ), свободной памяти ≈ 2,4 ГБ** — сервис и модель должны быть малыми; очистку диска владельцу стоит сделать отдельно.
- «Мозг» — Claude Code по подписке на ПК (лимиты подписки общие с интерактивной работой): один вызов `claude -p` на сообщение, без фоновых субагентов в чат-режиме; `/morning-run` — только по запросу.
- Токен бота — в `/opt/agents-my/.env`, вводит владелец сам командой, которую даст исполнитель; в чат и в git токен не попадает.
- Любые действия на VPS (деплой, systemd) — с подтверждения владельца.
- Компьютер владельца — Windows 11, PowerShell 5.1 для Планировщика.

## Оставлено исполнителю

Имя бота (предложить владельцу), порт API, формат хранения очереди, точные пороги сомнения, тексты кнопок, формат сводки, частота опроса слушателя (по умолчанию 3 с), устройство кнопочного запасного меню (по умолчанию: «Поставить задачу» → источник → группа → количество, переиспользуя выборку `/task`).

## Будущее (не в этом этапе)

Перенос «мозга» на VPS (Claude API, оплата по токенам) — чтобы ПК не был обязательным звеном; решение по цене после месяца работы этапа 2.
