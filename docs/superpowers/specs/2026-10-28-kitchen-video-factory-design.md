# Спек: кулинарный видео-завод — команда агентов, 6 площадок, план на неделю вперёд

_Статус: черновик, ждёт одобрения владельца (2026-10-28). Это «видео-цех», обещанный в спеке
2026-10-13-content-factory-orchestrator-design.md («тот же оркестратор, новые работники»), но для новой
ниши — кулинария. Климатический контур (СплитХаб, @Sendpr1ce_bot, content-factory) этот спек не меняет._

## 1. Зачем и что значит «готово»

Владелец выбрал нишу: **рецепты**. Каждый день 1–2 рецепта выходят на всех площадках сразу:

| Площадка | Что выходит по одному рецепту |
|---|---|
| YouTube | Shorts — вертикальный ролик 9:16 |
| TikTok | тот же ролик + своя подпись и хештеги |
| Instagram | Reels + подпись с рецептом |
| Facebook | Reels на странице |
| Telegram | ролик + альбом фото (подача, ингредиенты, шаги) + рецепт текстом |
| ВК | клип/видео + пост с фото и полным рецептом |

Участие владельца по умолчанию:
- раз в неделю одобряет план на 7 дней одной кнопкой; правки можно голосом;
- раз в день смотрит ленту готовых роликов и нажимает ✅. Когда площадка накопит 14 дней без отказов,
  ✅ на ней отключается — по той же лестнице L0–L3, что уже работает в ВК (`analytics/vk.py`).

**Готово (весь проект):** 14 дней подряд по 2 рецепта в день выходят на 6 площадках по расписанию.
Ни одной публикации без вердикта редактора. На VPS всегда лежит одобренный запас минимум на 3 дня:
десктоп часто выключен из-за перебоев с электричеством, см. CLAUDE.md фото-агента.

## 2. Что уже есть (разведка 2026-10-28)

- **Мозг:** Claude Code по подписке на ПК + субагенты + `claude -p` в безголовом режиме, слушатель
  (`listener/`) забирает задачи с VPS по SSH-туннелю. Бот оркестратора на VPS (`orchestrator_bot/`): голос
  (faster-whisper), таблица `drafts`, лента с кнопками ✅/❌, публикация только детерминированным кодом
  по кнопке. Правила каналов в `rules/*.yaml` + валидатор `tools/check_draft.py`.
- **Генерация:**
  - Grok-MCP `grok-imagine-xai` на ПК владельца (папка `tools/grok_imagine_mcp` в `GitHub/Content_factory`,
    упомянута в плане этапа 0).
  - Higgsfield MCP подключён к облачной сессии Claude. Проверка 2026-10-28: тариф `free`, **0 кредитов**.
  - Видеомодели в каталоге Higgsfield на 2026-10-28:
    - Seedance 2.5: 4–30 с, до 1080p, есть 9:16, звук, черновик 480p с доработкой до 1080p;
    - Grok Video 1.5: 2–15 с, из стартового кадра;
    - Kling 4.0: 3–30 с, 9:16, ключевые кадры.
- **TikTok:** аккаунт подключён к Higgsfield (`active` с 2026-08-28). Но публикация через Higgsfield требует
  ручной формы и файла, лежащего в Higgsfield. Поэтому это только запасной ручной путь, не конвейер.
- **Публикаторы content-factory:**
  - `publish/telegram.py` (Bot API);
  - `publish/vk.py` + OAuth VK ID (`publish/vk_oauth.py`).
  - Известная грабля ВК: ключ сообщества не грузит фото (ошибка 27), нужен пользовательский токен.
    Для загрузки видео ожидаем то же самое.
  - Также есть `dedupe.py`, UTM и сбор аналитики ВК.
- **Публикаторов YouTube / TikTok / Instagram / Facebook в коде нет:** в roadmap они не отмечены сделанными.

## 3. Команда агентов

```
Владелец ⇄ бот оркестратора (Telegram): план недели ✅, лента роликов ✅, голосовые правки
   │
   ▼  VPS: очередь, расписание, публикаторы 6 площадок, хранилище медиа, аналитика
ПК: слушатель → claude -p в репозитории кухни
   Оркестратор (главная сессия, /kitchen-week, /kitchen-day, /kitchen-revise)
     ├─ content-manager   — контент-менеджер: план на 7 дней, блюдо и рубрика на слот
     ├─ recipe-developer  — технолог: рецепт (граммы, шаги, время, порции)
     ├─ copywriter        — тексты: хук, титры, подписи под каждую площадку, хештеги, заголовок Shorts
     ├─ photo-director    — фото: промпты по «библии стиля», генерация кадров
     ├─ video-producer    — видео: раскадровка, image-to-video по кадрам, сборка мастер-ролика
     ├─ editor            — редактор-контролёр: рецепт, тексты, кадры, ролик; вердикт ok/не ok
     ├─ analyst           — аналитик: что зашло за неделю → вход для контент-менеджера
     └─ reporter          — итог дня владельцу (переиспользуется)
```

**Важное техническое ограничение:** в Claude Code субагент не может вызвать другого субагента.
Поэтому иерархия «оркестратор → контент-менеджер → исполнители» устроена так:
- контент-менеджер пишет **карточки заданий** (файл `brief.json` на каждый слот);
- раздаёт их исполнителям оркестратор (главная сессия);
- независимые шаги идут параллельно, несколькими вызовами Agent в одном сообщении (как в `/morning-run`).

| Агент | Модель | Инструменты | Пишет |
|---|---|---|---|
| content-manager | opus | Read, Write | `plan_week.json`, `slots/<слот>/brief.json` |
| recipe-developer | sonnet | Read, Write, WebSearch, WebFetch | `recipe.json` |
| copywriter | sonnet | Read, Write | `texts.json` |
| photo-director | sonnet | Read, Write, MCP генерации изображений | `images/*.png`, `images.json` |
| video-producer | sonnet | Read, Write, MCP генерации видео, Bash(`python tools/assemble.py:*`) | `video/master.mp4`, `video.json` |
| editor | opus | Read, Write, Bash(`python tools/check_*.py:*`, `python tools/frames.py:*`) | `verdicts/*.json` |
| analyst | sonnet | Read, Write | `analytics/week.json` |
| reporter | sonnet | Read, Write | `summary.md` |

**Жёсткие правила (будущий CLAUDE.md кухни):**
1. Агенты ничего не публикуют. Публикует только код на VPS: по ✅ владельца или по уровню автономии площадки.
2. В рецепте каждое число (граммы, минуты, градусы) проходит проверку. Температуры безопасности — только из
   таблицы `rules/food_safety.yaml`, где у каждой строки есть источник. Нет источника — нет цифры.
3. Никаких медицинских обещаний («лечит», «детокс», «сжигает жир») и цен.
4. Текст на изображениях и в видео **не генерируется нейросетью**: генераторы искажают буквы.
   Титры накладывает `tools/assemble.py` (ffmpeg).
5. Секреты не читаются и не выводятся. Ключи площадок живут только в `.env` на VPS.

## 4. Как идёт работа

### Неделя: `/kitchen-week` (воскресенье, 18:00, Планировщик Windows)
1. analyst читает статистику за прошедшую неделю → `analytics/week.json`: топ блюд, рубрик, хуков,
   удержание по площадкам.
2. content-manager составляет `plan_week.json` на 14 слотов (7 дней × 2). Учитывает:
   - сезон: в ноябре — тыква, яблоки, капуста;
   - ближайшие праздники;
   - баланс рубрик;
   - запрет повторов блюда за 30 дней (`dedupe`);
   - выводы аналитика.
3. editor проверяет план правилами: повторы, баланс, запрещённые темы.
4. Бот присылает владельцу таблицу недели с кнопками ✅ Одобрить / 🔄 Переделать. Правка голосом:
   «в среду вместо рыбы — блины».

### День: `/kitchen-day` — всегда готовим на **послезавтра** (запас на перебои ПК)
1. recipe-developer → `recipe.json`. Затем editor, проход 1 — рецепт: `tools/check_recipe.py` + оценка по смыслу.
2. Параллельно:
   - copywriter → `texts.json`;
   - photo-director → 4–6 кадров (подача, ингредиенты, 2–4 шага).
3. editor, проход 2 — кадры. Это **дешёвый шлюз перед дорогим видео:** видео делается только из принятых кадров.
4. video-producer:
   - раскадровка 5–7 сцен по 3–6 с;
   - image-to-video по каждому кадру (сначала черновик 480p, если модель умеет);
   - `tools/assemble.py`: склейка, титры, звук, финальная заставка → `master.mp4`.
5. editor, проход 3 — финал:
   - `tools/check_video.py` (ffprobe);
   - `tools/frames.py`: кадр каждые 2 с → осмотр на артефакты и соответствие рецепту;
   - `tools/check_texts.py`: лимиты площадок.
6. Отказ → одна переделка с замечаниями редактора, второй отказ окончательный (правило `/morning-run`).
   Слот уходит на запасной рецепт из плана.
7. Принятое слушатель отправляет на VPS. Бот присылает превью: ролик + подписи по площадкам + кнопки
   ✅ / ❌ / 🔄.
8. VPS публикует по расписанию слотов каждой площадки и сохраняет id/ссылку каждого поста.

### Статусы слота
`planned → recipe_ok → images_ok → video_ok → approved → scheduled → published:<площадка>`.
Ветки: `rejected`, `failed:<площадка>`. Повторное нажатие или повтор запроса не публикуют дважды:
ключ идемпотентности `kitchen|<id слота>|<площадка>`, как `editorial|<id>` в этапе 3.

## 5. Форматы и рубрики

**Мастер-ролик** (один на рецепт):
- 1080×1920, H.264 + AAC, 30 к/с;
- 20–45 с — с запасом укладывается в ограничения всех шести площадок;
- до 50 МБ — самый жёсткий лимит из шести: загрузка через Telegram Bot API.

Под площадки меняются подпись, хештеги, обложка, иногда длина.

**Рубрики на старт** (контент-менеджер чередует, аналитик потом перевешивает):
1. «Рецепт за 30 секунд» — основной формат, 5–7 сцен.
2. «Ужин из того, что есть» — 3–5 ингредиентов.
3. «Лайфхак / частая ошибка» — короткий ролик 10–15 с.
4. «Сезонное» — из продуктов месяца.
5. «Бюджетно» — без цен в тексте (правило 3), упор на простые продукты.

**Telegram:** подпись к видео ограничена 1024 символами. Поэтому выходят:
- видео с коротким хуком;
- следом альбом фото;
- следом сообщение с полным рецептом.

**ВК:** клип + пост с фото и полным рецептом. Подпись ВК длиннее, рецепт помещается целиком.

## 6. Фото → видео

- **Библия стиля** `rules/style.md`: одна «кухня-съёмочная площадка» на весь канал — стол, посуда, свет,
  цветокор, как выглядят руки. В каждый промпт входит блок стиля. Кадры одного рецепта генерируются
  от общего опорного кадра, чтобы тарелка и стол не менялись между сценами.
- **Изображения:** Grok-MCP на ПК или модель Higgsfield — по итогам A/B на этапе 2.
- **Видео:** image-to-video, стартовый кадр = принятое фото. Кандидаты: Grok Video 1.5 (Grok-MCP или Higgsfield),
  Seedance 2.5, Kling 4.0. Выбор на этапе 2 по трём мерам:
  - оценка редактора;
  - глаз владельца;
  - фактическое списание кредитов за ролик.
  Стоимость заранее не обещаем: считаем по факту прогона.
- **Сборка — детерминированный код**, `tools/assemble.py` на ffmpeg:
  - склейка сцен;
  - титры с ингредиентами и шагами;
  - нормализация громкости;
  - финальная заставка;
  - обложки под площадки.
- **Звук v1:** родной звук сцены от модели (шкворчание, нож) + музыкальная подложка **только из своей
  лицензированной библиотеки** `media/music/`. Популярные треки дают блокировки по авторскому праву.
  Озвучка диктором — опция на потом.
- **Бюджет:** лимит генераций на день в `config/kitchen.yaml`. Не больше 2 перегенераций на сцену.
  Превышение → слот в `failed`, сообщение владельцу. Тихого перерасхода нет.

## 7. Редактор-контролёр: что проверяется

Детерминированно (скрипты в `tools/`, с тестами, по образцу `check_draft.py`):
- `check_recipe.py`:
  - у каждого ингредиента есть количество и единица;
  - шаги используют только ингредиенты из списка;
  - порции > 0;
  - для птицы, фарша, яиц, грибов — обязательные формулировки готовности из `rules/food_safety.yaml`;
  - нет стоп-слов.
- `check_texts.py`: лимиты длины и хештегов по `rules/platforms.yaml`, стоп-слова, повтор хука за 30 дней.
- `check_video.py` (ffprobe): разрешение, длительность, частота кадров, есть звуковая дорожка, размер ≤ 50 МБ.

По смыслу (editor, opus), по кадрам из `tools/frames.py`:
- блюдо на кадрах совпадает с рецептом: нет ингредиентов, которых нет в списке;
- артефакты генерации: лишние пальцы, «плавящиеся» ножи и ложки, каракули вместо букв;
- аппетитность;
- хук в первые 2 секунды;
- грамотность.

`ok=true` только при оценке ≥ 4 из 5 и пройденных скриптах — как у нынешнего `critic`.

## 8. Публикация, расписание, автономия

- **Публикаторы на VPS:**
  - один модуль на площадку: `telegram`, `vk`, `youtube`, `tiktok`, `instagram`, `facebook`;
  - у каждого `dry_run: true` по умолчанию, ключ идемпотентности, повтор с паузой, алерт при ошибке;
  - Telegram и ВК — переиспользуем код content-factory.
- **Отметка ИИ-контента** на каждой площадке, где она есть: в TikTok API это поле `is_aigc`, на YouTube —
  отметка «изменённый или синтетический контент».
- **Слоты по умолчанию:** 12:00 и 19:00 по Москве на всех площадках, задаются в `config/kitchen.yaml`.
  Это стартовые значения, не «лучшее время»: дальше их двигает аналитика.
- **Автономия:** лестница L0–L3 из `analytics/vk.py`, отдельно по каждой площадке:
  - L1 — ✅ на всё;
  - L2 — автопубликация после 14 дней без отказов владельца;
  - три сбоя подряд → откат в L0.

## 9. Аналитика

Ежедневный сбор на VPS: просмотры, досмотры/удержание, лайки, комментарии, репосты, подписки.

| Площадка | Источник |
|---|---|
| YouTube | Data API + Analytics API |
| TikTok | Content API |
| Instagram, Facebook | Insights |
| ВК | готовый сборщик content-factory |
| Telegram | личный Telegram-MCP `get_post_stats`: Bot API не отдаёт просмотры постов канала |

Раз в неделю analyst сводит `analytics/week.json`, и это первый вход для плана следующей недели.
Так замыкается «прогнозирует»: план опирается на то, что реально набрало досмотры, а не на догадки.

## 10. Где живёт код (рекомендация)

**Отдельный репозиторий `kitchen_autopilot`.** Его создаёт владелец на GitHub вручную: создание репо
у нас блокируется trade controls. Причины:
- корневой `CLAUDE.md` этого репозитория целиком про СплитХаб, а Claude Code подгружает CLAUDE.md
  из всех родительских папок — климатические правила просочились бы в кухню;
- другой бренд, аудитория, правила и риски.

Код при этом не пишем заново:
- из Agents_MY берём схему слушателя, таблицу `drafts` и ленту с кнопками, голос;
- из content-factory берём `publish/telegram.py`, `publish/vk.py`, `vk_oauth`, `dedupe.py`, L0–L3.

## 11. Этапы

| # | Этап | Готово, когда | Проверка |
|---|---|---|---|
| 0 | **Доступы и проверка площадок** (в основном владелец) | таблица «площадка → способ публикации → результат пробной закрытой публикации» заполнена по всем 6 | пробные закрытые публикации: YouTube — `private`, TikTok — черновик/`SELF_ONLY`, IG/FB — тестовый аккаунт, ВК — пользовательский токен с правом на видео, Telegram — тестовый канал; запросы с VPS доходят до API Google, TikTok, Meta |
| 1 | **Каркас команды агентов** | `/kitchen-day` на тестовую дату пишет recipe/texts/brief/verdicts | `pytest` зелёный по `check_recipe`/`check_texts`; прогон без генерации медиа |
| 2 | **Фото- и видео-цех** | 5 мастер-роликов 1080×1920 проходят `check_video` и редактора | A/B: 3 видеомодели × 5 блюд, сравнение по оценке редактора, глазу владельца и списанию кредитов |
| 3 | **Лента одобрения + Telegram и ВК** | ролик с подписями приходит в бот, ✅ публикует в тестовые TG/ВК | тесты публикаторов на фейковом HTTP; один ✅ = ровно одна публикация |
| 4 | **YouTube Shorts + TikTok** | ✅ публикует ролик на обе площадки | закрытые публикации, затем публичные после аудитов |
| 5 | **Instagram + Facebook Reels** | ✅ публикует на обе площадки | то же |
| 6 | **План на неделю + расписание + запас** | 7 дней выходят по слотам сами после ✅ плана, запас на VPS ≥ 3 дней | неделя на тестовых каналах |
| 7 | **Аналитика + автономия L0–L3** | недельный отчёт приходит, план следующей недели ссылается на него | журнал автономии считает отказы, откат при 3 сбоях проверен тестом |

Порядок не случаен:
- Telegram и ВК первыми — публикаторы уже есть;
- YouTube и TikTok следом — это главные площадки для шортсов;
- Meta последней — там больше всего трений с доступом (раздел 12).

Аудиты YouTube и TikTok идут неделями, поэтому заявки подаём уже на этапе 0, параллельно с разработкой.

## 12. Риски, которые нельзя пропустить

1. **Регион и санкции.** GitHub уже блокирует создание репозиториев по trade controls. Google, Meta и TikTok
   тоже могут ограничивать API, аккаунты и монетизацию для региона. Проверяется пробными публикациями
   этапа 0, до написания публикаторов.
2. **TikTok.** В марте 2022 TikTok закрыл загрузку нового контента для пользователей в России.
   Действует ли это для вашего аккаунта — первая проверка этапа 0.
   Неаудированное приложение TikTok публикует только с видимостью `SELF_ONLY`. Нужен аудит приложения,
   либо запасной путь: черновик → владелец публикует в приложении.
3. **YouTube.**
   - Видео, загруженные через API из непроверенного проекта Google Cloud, блокируются как приватные
     до аудита.
   - Квота по умолчанию — 10 000 единиц в сутки, загрузка ролика стоит 1 600. Это до 6 роликов в сутки:
     для 2 в день хватает.
4. **Meta (Instagram, Facebook).**
   - Обе сети заблокированы в РФ, Meta признана в РФ экстремистской организацией (2022).
   - Запросы к API с российского сервера могут не проходить → понадобится прокси.
   - Реклама на заблокированных ресурсах в РФ запрещена законом с 1 сентября 2024 года.
   - Органический постинг — решение владельца; для своих аккаунтов хватает приложения Meta в режиме
     разработки, где владелец — администратор.
5. **ВК:** загрузка видео, скорее всего, тоже потребует пользовательский токен, как фото (ошибка 27 у ключа
   сообщества уже была).
6. **Однотипный ИИ-контент** площадки занижают в выдаче. Защита: чередование рубрик и шаблонов монтажа,
   запрет повторов, честная ИИ-маркировка.
7. **Неверный рецепт** — главный репутационный риск. Защита: технолог + `food_safety.yaml` с источниками
   + три прохода редактора.
8. **Музыка** — только своя лицензированная библиотека.
9. **Деньги на генерацию.** Higgsfield на этом аккаунте сейчас `free` с 0 кредитов. Дневной лимит в конфиге,
   шлюз «фото до видео», черновики 480p.
10. **ПК выключается** → готовим на послезавтра, запас на VPS ≥ 3 дней, VPS публикует без ПК.
