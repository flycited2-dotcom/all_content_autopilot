# Спек: контент-завод — оркестратор над TG + ВК (Agents_MY)

_Статус: одобрен владельцем 2026-10-13; дополнен в тот же день — Telegram-оркестратор и голос (этап 2). Этапы 0–6; видео-цех — отдельный спек._

## Context

Владелец работает один, основной фокус — тендеры. Контент (Telegram-канал «СплитХаб.ру», группа ВК, позже YouTube/TikTok) сейчас требует ручной проверки каждого поста в нескольких чатах. Цель — «контент-завод»: утром одна задача → оркестратор раздаёт работу агентам → агенты-контролёры проверяют по заданным правилам → прошедшее публикуется. Участие владельца — одна утренняя задача, одна лента на одобрение, вечерний отчёт.

**Решения владельца:**
- Автономия **поэтапная**: сначала всё одобряет владелец пачкой; автопубликация включается отдельно по каждому каналу после 1–2 недель без ошибок контролёров.
- Архитектура **гибрид**: VPS 24/7 — диспетчер, правила, публикация, бот; ПК — «думающая» часть и тяжёлая генерация.
- «Мозг» — **Claude Code на ПК по подписке** (без API-ключа). Если ПК выключен, VPS продолжает работать как сейчас (таймеры content-factory), задачи ждут в очереди.
- **Интерфейс — отдельный Telegram-бот оркестратора**, закреплённый у владельца: утренний бриф, правки в течение дня, вечерний отчёт — всё в одном чате.
- **Голос — основной ввод**: бриф, правки к черновикам, одобрение, вопросы о статусе. Перед любым действием бот отвечает «Понял так: …»; публикация и прочие необратимые действия — только после кнопки ✅.
- Личный Telegram-аккаунт владельца (MCP `telega_agent_personal`, 57 инструментов, уже подключён к Claude/ChatGPT/Codex/Claude Code) — **«руки», а не собеседник**: чтение прайсов и рабочих чатов, статьи с фото в канал, статистика, расшифровка голоса (Whisper). Агентам — только чтение; отправка — через его же схему «черновик → предпросмотр → подтверждение».
- Первый этап — **мозг над TG + ВК**. Видео-линия (YouTube/TikTok) — второй отдельный подпроект со своим спеком.

**Что уже есть (по итогам разведки), переиспользуем, а не пишем заново:**
- `GitHub/content-factory` (канон, ~20k строк, ~725 тестов): сбор товаров → цена → карточка (фото-агент на ПК через ChatGPT) → `review/rules.py` → кнопки ✅❌🔄💰 в канале проверки бота @Sendpr1ce_bot → публикация. ВК-планер `orchestrator/vk_content_plan.py` (машина статусов, кнопки `vkp:*`), детерминированные агенты `agents/editorial.py` (Idea/Research/VkEditorial/Visual/**StrictCritic** + `EditorialAuditStore`), уровни автономии L0–L3 с автооткатом в `analytics/vk.py`, `dedupe.py`, рубильник `orchestrator/generation.py`, публикаторы `publish/telegram.py` и `publish/vk.py` (dry-run по умолчанию), MCP-по-SSH шаблон `tender_mcp.py`.
- Схема «ПК забирает задания с VPS» уже работает у фото-агента (`agent_convert_foto_rituailb2b2`, API :8765 + SSH-туннель).
- Принцип владельца: **товарные посты с ценами — только шаблоны, нейросеть не трогает цены и характеристики.** Сохраняем.

## Архитектура

```
Владелец ⇄ бот оркестратора (Telegram, закреплён): текст / голос / кнопки
   │ VPS: orchestrator-bot (long-poll 24/7) — очередь сообщений, расшифровка голоса,
   │      эхо «Понял так», детерминированные ответы (статус, отчёт), если ПК выключен
   ▼
ПК: agent-listener (резидентный процесс, забирает очередь по SSH, как фото-агент)
   └▶ claude -p … --resume <сессия дня> в Agents_MY
        Оркестратор (главная сессия)
          ├─ субагенты-работники: researcher, tg-editor, vk-editor, product-planner
          ├─ субагент-контролёр: critic (+ tools/check_draft.py, + правила VPS)
          ├─ инструменты: factory-MCP (SSH → content-factory), личный Telegram-MCP (чтение)
          └─ ответ владельцу в чат: итог, черновики с кнопками ✅❌🔄, вопросы
VPS: content-factory публикует только одобренное → вечерний отчёт 21:00 в чат оркестратора
```

**Связь ПК ↔ VPS — MCP-сервер поверх SSH** (`factory_mcp.py` по образцу `tender_mcp.py`, ключ `id_ritualb2b_claude`). Клиент — Claude Code; никаких новых открытых портов. Инструменты сначала только на чтение, запись — узким набором, и каждый «пишущий» инструмент кладёт черновик в статус `review`, а не публикует.

### Этап 1 — Каркас Agents_MY
- `git init`, `CLAUDE.md` (роль, жёсткие запреты: не выдумывать цены/характеристики, не публиковать в обход `review`, не трогать продакшен-конфиги).
- `.claude/agents/`: `tg-editor.md`, `vk-editor.md`, `product-planner.md`, `researcher.md`, `critic.md`, `reporter.md` — каждый с узким набором инструментов.
- `.claude/commands/morning-run.md` — сценарий оркестратора (прочитать бриф → план → раздать → собрать → критик → отправить → итог).
- `rules/` — YAML правил качества по каналам (длина, обязательные элементы, стоп-слова, частота, CTA, «каждое число подтверждено фактом» — логика `StrictCriticAgent`).
- `.mcp.json` не нужен до этапа 3 (factory-MCP); личный Telegram-MCP подключается на этапе 2 только на чтение.
- `.claude/settings.json`: allowlist инструментов для безголового запуска.

### Этап 2 — Telegram-оркестратор и голос
- Владелец создаёт нового бота в @BotFather и передаёт токен в `.env` на VPS (не в чат, не в git).
- VPS: сервис `orchestrator-bot` (отдельный от `cf-bot`): принимает только чат владельца; текст/голос/ответы на сообщения/нажатия кнопок → очередь (SQLite). Голос — сохраняется оригинал, сразу эхо «Понял так: …». Если ПК молчит > 2 мин — «Принял, разберу, когда ПК будет на связи»; команды статуса отвечаются без ПК.
- ПК: `agent-listener` забирает очередь через SSH-туннель (схема `remote_agent.py` фото-агента), на каждое сообщение запускает `claude -p` с `--resume` сессии дня, ответ уходит обратно в бот. Автозапуск — Планировщик Windows при входе.
- Расшифровка голоса: Whisper — либо `faster-whisper` на ПК, либо `transcribe_voice` личного MCP на VPS. Выбор — первым шагом плана этапа 2, по качеству на 5 реальных голосовых владельца (длинная диктовка, шум, бренды).
- Сценарии голосом: бриф → `/morning-run`; правка (голосовой ответ на черновик) → редактор переписывает → critic заново; одобрение («первые три публикуй») → бот показывает понятое + кнопка ✅, без неё ничего не выполняется; вопрос («что вышло вчера?») → ответ из `runs/` и отчётов.
- На этом этапе публикации всё ещё нет: черновики приходят в чат как предпросмотр; публикация подключается на этапе 3.

### Этап 3 — factory-MCP на VPS (в репозитории content-factory)
Новый `src/content_factory/factory_mcp.py`, переиспользует существующие хранилища:
- Чтение: `get_brief`, `factory_status` (очереди, ожидающие проверки, опубликованное сегодня, ошибки), `list_vk_plan`, `list_catalog` (наличие/цены из уже собранных источников), `recent_posts` (для антидублей).
- Запись (всё в статус `review`): `enqueue_product_task` (через `TaskQueue`/`select_items`, как `/make`), `submit_vk_draft` (в `VkContentPlanStore` + `EditorialAuditStore` с вердиктом критика), `submit_tg_editorial` (не-товарный пост в канал проверки).
- Повторные проверки на VPS: `review/rules.py` + `dedupe.py` перед выводом в ленту, независимо от вердикта LLM-критика.

### Этап 4 — Расписание и единая лента
- ПК: утренний прогон по Планировщику Windows (08:00 и при входе в систему), если бриф не пришёл раньше голосом; лог в `Agents_MY/runs/`.
- Лента: один дайджест-пост в чате оркестратора «готово N, прошли проверку M, отклонено K» с кнопками «✅ Одобрить все прошедшие» / «Смотреть по одному»; существующие кнопки ✅❌🔄💰 и `vkp:*` продолжают работать.

### Этап 5 — Вечерний отчёт
Таймер `cf-agent-report` 21:00 (детерминированный, на VPS): опубликовано по каналам, отклонено и почему, ошибки, заявки «📩 Заказать», статус ПК-задач.

### Этап 6 — Поэтапная автономия
Обобщить L0–L3 из `analytics/vk.py` на каналы TG-editorial / TG-товары / ВК. Журнал доверия: совпадение вердикта контролёра с решением владельца. Повышение уровня предлагается ботом (не автоматически) после 14 дней ≥95% совпадений; автооткат в L0 при ошибках сохраняется. Товарные посты с ценой остаются на ручном одобрении дольше всех.
